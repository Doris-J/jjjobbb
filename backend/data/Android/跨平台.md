# 跨平台面试八股文（Flutter / React Native）

## 一、Flutter

### Q1：Flutter 渲染原理？

**三棵树：**

```
Widget Tree（配置描述，不可变，频繁重建）
    ↓ createElement()
Element Tree（实例，持有状态，连接 Widget 和 RenderObject）
    ↓ createRenderObject()
RenderObject Tree（负责布局和绘制）
```

**渲染流程：**

```
Dart 代码
    → Widget 树构建
    → RenderObject 布局（layout）
    → RenderObject 绘制（paint）→ Layer Tree
    → Skia / Impeller 光栅化
    → GPU 显示
```

**与原生渲染对比：**

| | Flutter | React Native | 原生 Android |
|--|---------|-------------|-------------|
| 渲染方式 | 自绘（Skia/Impeller） | 调用原生控件 | 原生控件 |
| 语言 | Dart | JavaScript | Kotlin/Java |
| UI 一致性 | 完全跨平台一致 | 平台差异 | 平台原生风格 |
| 性能 | 接近原生 | 中等（Bridge 开销） | 最佳 |
| 包体积 | 较大（含 Skia 引擎） | 中 | 小 |

### Q2：Flutter 与 Native 通信（Platform Channel）？

**三种 Channel：**

```dart
// 1. MethodChannel：方法调用，双向，一次性
static const platform = MethodChannel('com.example/battery');

Future<void> getBatteryLevel() async {
    try {
        final level = await platform.invokeMethod<int>('getBatteryLevel');
    } on PlatformException catch (e) { }
}
```

```kotlin
// Android Native 端
MethodChannel(flutterEngine.dartExecutor.binaryMessenger, "com.example/battery")
    .setMethodCallHandler { call, result ->
        when (call.method) {
            "getBatteryLevel" -> result.success(getBatteryLevel())
            else -> result.notImplemented()
        }
    }
```

```dart
// 2. EventChannel：Native → Dart 持续数据流（传感器、位置）
static const eventChannel = EventChannel('com.example/sensor');
Stream<dynamic> get sensorStream => eventChannel.receiveBroadcastStream();
```

```dart
// 3. BasicMessageChannel：持续双向通信，自定义编解码器
static const messageChannel = BasicMessageChannel<String>('com.example/msg', StringCodec());
final reply = await messageChannel.send('Hello Native');
```

### Q3：Flutter 性能优化？

```dart
// 1. const 构造函数（避免不必要重建）
const Text('Hello World')

// 2. ListView.builder（懒加载）
ListView.builder(
    itemCount: list.length,
    itemBuilder: (context, index) => ItemWidget(list[index]),

// 3. RepaintBoundary（隔离重绘区域）
RepaintBoundary(child: ComplexAnimationWidget())

// 4. Isolate 处理 CPU 密集型任务
Future<String> computeInIsolate(String input) async {
    return await compute(heavyFunction, input);
}

// 5. shouldRebuild 优化
@override
bool updateShouldNotify(MyInheritedWidget oldWidget) {
    return data != oldWidget.data;
}
```

## 二、React Native

### Q5：RN 桥接原理？

**旧架构（Bridge）：**

```
JS Thread
    ↓ 序列化为 JSON
Bridge（异步消息队列）
    ↓ 反序列化
Native Thread（UI Thread / Shadow Thread）
```

**问题：** 跨线程序列化开销大，Bridge 是性能瓶颈，无法同步获取 Native 值。

**新架构（JSI + Fabric + TurboModules）：**

```
JS ←→ JSI（C++ 层）
         ↓ 直接调用（无序列化）
TurboModule（按需加载）
Fabric（支持同步渲染，优先级调度）
```

---

### Q6：RN 与 Flutter 选型？

| 维度 | Flutter | React Native |
|------|---------|-------------|
| 渲染 | 自绘引擎，UI 完全一致 | 调用原生组件，平台风格 |
| 语言 | Dart | JavaScript / TypeScript |
| 热更新 | ❌ 不支持 | ✅ 支持（CodePush） |
| 适合团队 | 移动端团队 | 前端 / 全栈团队 |

## 三、跨平台方案全局对比

### Q7：各跨平台方案对比？

| 方案 | 渲染 | 语言 | 性能 | 热更新 | 适用场景 |
|------|------|------|------|--------|---------|
| Flutter | 自绘（Skia） | Dart | ⭐⭐⭐⭐ | ❌ | UI 一致性要求高 |
| React Native | 原生控件 | JS/TS | ⭐⭐⭐ | ✅ | 前端团队，快速迭代 |
| Compose Multiplatform | 原生/自绘 | Kotlin | ⭐⭐⭐⭐ | ❌ | Android 团队，KMP 项目 |
| WebView（H5） | WebView | HTML/JS | ⭐⭐ | ✅ | 活动页，运营页 |
| 原生 | 原生 | Kotlin/Java | ⭐⭐⭐⭐⭐ | ❌ | 高性能，平台特定功能 |

**混合开发策略（实际项目推荐）：**

```
核心功能 / 高性能模块     → 原生开发（Camera / 支付 / 蓝牙）
通用业务页面             → Flutter / RN
活动页 / 运营推广页       → WebView（H5，可热更新）
工具类 SDK              → Kotlin Multiplatform
```
