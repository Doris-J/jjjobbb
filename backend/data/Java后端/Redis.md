# Redis

### Q1：Redis 为什么这么快？ [easy]

1. 纯内存操作，避免磁盘 IO
2. 单线程模型（命令处理），避免多线程上下文切换和锁竞争
3. IO 多路复用（epoll），单线程处理大量并发连接
4. 高效数据结构：SDS、跳表、压缩列表等
5. 6.0+ 引入多线程处理网络 IO，进一步提升吞吐

### Q2：缓存穿透、缓存击穿、缓存雪崩分别是什么？如何解决？

缓存穿透：查询不存在的数据，每次都打到数据库。
解决：布隆过滤器拦截无效请求；缓存空值（TTL 短一些）。

缓存击穿：热点 key 过期，大量请求同时打到数据库。
解决：互斥锁（只让一个请求回源，其他等待）；热点 key 永不过期 + 异步更新。

缓存雪崩：大量 key 同时过期，或 Redis 宕机。
解决：过期时间加随机值；Redis 高可用（主从+哨兵/集群）；限流降级。

### Q3：Redis 持久化方式有哪些？ [choice|easy]

- A. RDB 和 AOF
- B. 只有 RDB
- C. 只有 AOF
- D. RDB、AOF 和混合持久化 ✓

RDB（Redis Database）：定时将内存数据快照写入磁盘，文件小、恢复快，但可能丢失最后一次快照后的数据。

AOF（Append Only File）：记录每条写命令，持久化更安全，但文件大、恢复慢。

RDB + AOF 混合持久化（Redis 4.0+）：AOF 重写时用 RDB 格式保存全量数据，后续追加 AOF 日志，兼顾安全性和恢复速度。
