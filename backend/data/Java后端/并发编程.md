# 并发编程

### Q1：synchronized 和 ReentrantLock 有什么区别？

1. 实现：synchronized 是 JVM 关键字，ReentrantLock 是 Java API
2. 等待可中断：ReentrantLock 可以响应中断，synchronized 不能
3. 公平锁：ReentrantLock 支持公平/非公平，synchronized 只有非公平
4. 多个条件变量：ReentrantLock 可绑定多个 Condition，synchronized 只有一个 wait/notify
5. 锁释放：synchronized 自动释放，ReentrantLock 需要手动 unlock（要放在 finally 中）
6. 性能：JDK 1.6 后 synchronized 有锁升级优化，两者性能差距不大

### Q2：volatile 关键字的作用是什么？

1. 可见性：保证变量修改后立即写回主内存，读取时从主内存读，不使用线程本地缓存
2. 禁止指令重排序：通过内存屏障（Memory Barrier）实现

注意：volatile 不保证原子性。例如 i++ 操作（读-改-写三步）不是原子的，volatile 无法保证。

适用场景：
- 状态标志位（boolean stopped）
- 双重检查锁定（DCL）单例模式中的实例变量

### Q3：ThreadLocal 的原理是什么？会导致内存泄漏吗？ [hard]

原理：每个 Thread 内部有一个 ThreadLocalMap，键是 ThreadLocal 实例（弱引用），值是实际存储的对象。

内存泄漏原因：
- ThreadLocal 是弱引用，GC 后 key 变为 null
- 但 value 是强引用，如果线程不销毁（线程池），value 永远不会回收

解决：使用完后调用 ThreadLocal.remove() 清除 value。
